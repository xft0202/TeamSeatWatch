# ADR-0005: 单人本地部署采用密码登录

- 状态：Accepted
- 日期：2026-09-24
- 取代：ADR-0003 的 Owner 认证第 4 项，以及其中把 TOTP/恢复码作为 Owner 登录必需因素的相关实现约束

## 背景

TeamSeatWatch V1 的 Owner 是本机上的唯一系统所有者，不提供公网注册、多运营者协作或托管 SaaS。当前登录流程要求先输入密码，再输入 TOTP 或一次性恢复码。对个人本地部署而言，这个额外交互不是可接受的产品体验，且本机部署者已经直接控制运行环境和数据库。

## 决定

1. Owner 管理端使用用户名加密码登录，不再要求 TOTP、恢复码或任何第二因素。
2. 继续保留 Argon2id 密码哈希、未知账号的等时校验、账号/IP 登录限速、统一失败响应、主机 CLI 创建/重置、认证审计和旧会话撤销。
3. 继续保留会话令牌哈希、`HttpOnly`、`SameSite=Strict`、闲置 8 小时、绝对 24 小时过期、敏感动作后的会话轮换、Origin 校验和 CSRF 双提交校验。
4. 现有 Owner 表中的 TOTP 加密材料与恢复码表保留兼容字段，既有数据库通过迁移允许这些 Owner 字段为空；它们不再参与登录授权。
5. Owner 登录审计记录认证方法为 `password`。历史 TOTP/恢复码审计记录仍可读取，不重写历史事实。
6. 目标成员账号用于平台 OAuth 交付的密码、TOTP 和恢复秘密不属于本决策范围，仍按平台交付流程使用。

## 后果

- 本地个人使用登录只需要一组用户名和密码。
- 本机泄露或密码泄露的风险更高，因此密码长度、主机文件权限、数据库权限、HTTPS/mTLS 边界和会话撤销仍是必要保护；移除第二因素不能被解释为移除其他认证边界。
- 未来如果部署为多人、远程或托管服务，必须新增架构决定重新引入更强认证，不得直接沿用本地密码模式。
